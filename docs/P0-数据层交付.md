### 2.3 新表结构（4 张）

```sql
-- 1. 景点表
t_attraction(景点ID PK, 景点名称, 类型, 位置, 开放时间)
        + INDEX(类型)

-- 2. 游客表
t_visitor(游客ID PK, 姓名, 性别, 年龄, 地区)
        + INDEX(年龄), INDEX(性别)

-- 3. 消费表
t_consumption(消费ID PK, 时间, 游客ID, 景点ID, 消费金额)
        + INDEX(游客ID, 景点ID, 时间, 景点ID+时间)

-- 4. 游玩记录表
t_visit_record(记录ID PK, 时间, 游客ID, 景点ID, 游玩时长)
        + INDEX(游客ID, 景点ID, 时间, 景点ID+时间)
```

所有表 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`。

## 三、Docker 部署步骤

> 本项目用 Docker Compose 部署，**不需要单独的 VM**。以下命令在本机执行即可。

### 3.1 前置条件

- 已 `git clone` 本仓库并 `cd` 到项目根目录
- 已 checkout 到合并后分支（master 或 develop）
- Docker Desktop / Docker Engine ≥ 4.10，内存 ≥ 16GB
- Python ≥ 3.8，已装 `pymysql`（`pip install pymysql`）

### 3.2 准备 CSV 数据

```bash
# data/ 目录已在 .gitignore 里，需要手动复制 CSV 到 data/raw_data/
# 从作业题提供的数据集（Topic 18）拷贝 4 个 CSV：
#   attractions.csv     10 行
#   visitors.csv        10000 行
#   consumption.csv     100000 行
#   visit_records.csv   100000 行

# 把 CSV 放到项目 data/raw_data/（不进 git）
mkdir -p data/raw_data
# 从 D:\选题与数据相关资料\数据集\Topic 18\ 复制 4 个 CSV 进来
# 或自行生成/准备

# 验证
ls -lh data/raw_data/
# 期望:
#   attractions.csv     ~443B
#   visitors.csv        ~393KB
#   consumption.csv     ~4.0MB
#   visit_records.csv   ~3.8MB
```

### 3.3 重置 MySQL（新 DDL 生效）

```bash
# 1. 停 MySQL，删 volume（清空旧数据）
docker compose down mysql
docker volume rm smart-scenic-bigdata_mysql-data

# 2. 启 MySQL（首次启动会自动跑 /docker-entrypoint-initdb.d/01-init-business.sql）
docker compose up -d mysql

# 3. 等待 30s，确认 DDL 已跑
sleep 30
docker exec mysql mysql -uroot -proot123 -e "USE scenic; SHOW TABLES;"
# 期望: 4 张表 t_attraction / t_visitor / t_consumption / t_visit_record
```

### 3.4 加载 CSV 到 MySQL

```bash
# 1. 确保 pymysql
pip install pymysql

# 2. 跑加载脚本（容器外，连接容器内 MySQL）
python scripts/load-csv-to-mysql.py

# 期望输出:
#   t_attraction:    10
#   t_visitor:    10000
#   t_consumption: 100000
#   t_visit_record: 100000
```

### 3.5 重建 hadoop-namenode 镜像（新 sqoop 脚本）

```bash
# sqoop-import-mysql.sh 烤进镜像，必须 rebuild
docker compose build hadoop-namenode
docker compose up -d --force-recreate hadoop-namenode

# 等待 ~30s 容器起来
sleep 30
docker ps | grep hadoop-namenode   # 状态应为 Up
```

### 3.6 触发 Sqoop 导入 HDFS

```bash
docker exec hadoop-namenode bash /opt/jobs/sqoop-import-mysql.sh

# 期望输出:
#   4 张表依次导入
#   --> 10 rows written to /scenic/sqoop/t_attraction/
#   --> 10000 rows written to /scenic/sqoop/t_visitor/
#   --> 100000 rows written to /scenic/sqoop/t_consumption/
#   --> 100000 rows written to /scenic/sqoop/t_visit_record/
```

### 3.7 端到端验证

```bash
# 1. MySQL 数据量
docker exec mysql mysql -uroot -proot123 -e "
  SELECT 't_attraction' t, COUNT(*) n FROM t_attraction UNION
```

## 四、注意事项

### 4.1 不要漏掉的步骤

1. **`chmod +x` 两个 sh 脚本**（git 不保留 Windows 文件权限位）
2. **rebuild hadoop-namenode 镜像**（sqoop 脚本是烤进镜像的）
3. **删 mysql-data volume**（否则新 DDL 不生效）

### 4.2 排错指南

| 现象 | 原因 | 解决 |
|---|---|---|
| `bash: ./scripts/load-csv-to-mysql.sh: /bin/bash^M: bad interpreter` | 行尾是 CRLF | `dos2unix scripts/load-csv-to-mysql.sh` |
| `ModuleNotFoundError: No module named 'pymysql'` | 没装 | `pip install pymysql` |
| `Can't connect to MySQL server` | MySQL 还没起 | `sleep 30` 后重试 |
| `Table 'scenic.t_attraction' doesn't exist` | 没删 volume | 重做 3.3 |
| Sqoop 报 `Unknown column 'xxx' in 'field list'` | MySQL 还是旧 schema | 重做 3.3 |
| Sqoop 报 `Could not find any column` | 列名含中文，编码问题 | 确认 `characterEncoding=utf8` 在 JDBC URL 中（已加） |

### 4.3 与 P0 无关但需知晓的现有限制

- Sqoop 脚本对 10w+ 行的 `t_consumption` / `t_visit_record` 用 1 个 mapper，速度约 30-60s，可接受
- `t_visit_record` 没有 `satisfaction` 字段（作业要求里也没有），后续 ML 任务的"满意度"需要自己构造（如用"消费金额"或"游玩时长"代理）
