## 二、选题十八 智能景区管理系统

### 2.1 项目背景

为了提高景区的运营效率和游客满意度，实时监控和分析景区数据（如游客数据、景点数据、消费数据等）是至关重要的。本作业将基于大数据平台模拟一个智能景区管理系统，学生需要完成数据采集、存储、处理、分析及可视化展示等任务。

### 2.2 项目要求

#### 1. 数据采集与存储

- 提供多个 CSV 格式的初始数据集（或自选数据集），包括：
  - **游客数据**（`visitors.csv`）：游客ID、姓名、性别、年龄、地区
  - **景点数据**（`attractions.csv`）：景点ID、景点名称、类型、位置、开放时间
  - **消费数据**（`consumption.csv`）：消费ID、时间、游客ID、景点ID、消费金额
  - **游玩记录数据**（`visit_records.csv`）：记录ID、时间、游客ID、景点ID、游玩时长
- 将这些数据集导入到 MySQL 数据库中，并创建相应的表结构
- 使用 Sqoop 将历史景区数据从 MySQL 导入到 HDFS 中
- 在 HBase 中创建表结构，并将处理后的数据存储到 HBase 中

#### 2. 数据处理与分析（使用 Spark）

**基础分析**：
- 使用 Spark 进行数据清洗，去除噪声和无效数据
- 计算各景点的游客数量、平均游玩时长、消费金额等基础指标

**高级分析**：
- **游客分析**：分析不同年龄段和地区的游客分布，找出主要游客群体，并提出营销建议
- **景点分析**：基于景点数据，分析不同时间段的景点热度，找出最受欢迎的景点
- **消费分析**：使用关联规则算法（如 Apriori）分析游客消费行为与景点的关联，评估游客的消费偏好

**机器学习**：
- **回归分析**：使用回归模型（如线性回归、Lasso 回归、Ridge 回归等）预测未来的游客数量和消费金额
- **聚类分析**：使用 K-means 或 DBSCAN 等聚类算法，对游客数据进行聚类分析，识别不同特征的游客群体
- **分类分析**：使用分类模型（如决策树、随机森林等），分类不同游客的游玩行为（如高消费、低消费、频繁游玩）

#### 3. 数据整合与查询

- 在 HDFS 上使用 Hive 创建表结构，对数据进行分区存储和管理，提高查询效率
  - 创建分区表，根据时间、景点等进行分区存储
  - 创建视图，简化复杂查询，提高查询效率
  - 使用 HiveQL 进行复杂查询，如计算每个景点的日均游客数量、查询高消费游客、对比不同时间段的景点热度等
- 在 HBase 中存储实时游玩记录数据，并进行快速查询
  - 创建表结构，包括列族和列，如：时间、游客ID、景点ID、游玩时长
  - 使用 HBase API 对实时数据进行快速查询和分析

#### 4. 可视化分析

- 搭建一个可视化平台，展示景区数据分析结果，包括游客分布图、景点热度图、消费偏好图等
- 实现数据的动态更新功能，根据时间段或景点选择展示不同的景区数据

### 2.3 项目交付

1. **源代码**：完整的项目源代码，包括代码、数据集、数据库脚本、前后端脚本等
2. **项目文档**：项目实习报告（包括项目背景、功能需求、技术选型、系统架构、数据库设计、接口设计、使用说明等）、汇报 PPT

#### Spark Streaming 启动方式

```bash
# 1. 确保 spark-master 容器内有作业脚本（首次需 docker cp）
docker cp app/jobs/spark/streaming_visit.py spark-master:/opt/jobs/spark/
docker cp app/jobs/spark/run-streaming.sh   spark-master:/opt/jobs/spark/

# 2. 启动 streaming 任务（首次会下载 spark-sql-kafka 包 ~5MB）
docker exec spark-master bash /opt/jobs/spark/run-streaming.sh

# 3. 测试：发 1 条事件到 Kafka
docker exec kafka-1 /opt/kafka/bin/kafka-console-producer.sh \
    --bootstrap-server localhost:9092 --topic scenic_events <<< \
    '{"type":"event","visitor_id":"V001","attraction_id":"A01","event_type":"enter","ts":1700000000000}'

# 4. 验证：查 HBase scenic_realtime
docker exec hbase-master hbase shell -n <<< "scan 'scenic_realtime', {LIMIT => 5}"
```

#### 模型持久化使用方式

```bash
# 1. 启动后端（自动加载 HDFS /scenic/models/，没有就训练并持久化）
uvicorn app.backend.main:app --port 8000

# 2. 查看模型仓库状态
curl http://localhost:8000/api/predict/status

# 3. 强制重训并写回 HDFS（用于更新训练数据后）
curl -X POST http://localhost:8000/api/predict/retrain

# 4. 直接看 HDFS 上的模型
docker exec hadoop-namenode hdfs dfs -ls -R /scenic/models/
```
